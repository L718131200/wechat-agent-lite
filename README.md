# wechat-agent-lite

微信 AI 机器人的**业务层**。只管"什么时候回、回什么、怎么切句子"；收发消息、下载图片、操作微信窗口交给引擎 [`wechatauto-replica`](https://github.com/fanyuantaier/wechatauto-replica)。

> **本项目只做上层。** 引擎是别人的（Apache-2.0），本包 100% 自己写。
> 引擎升级时 `pip install -U wechatauto-replica` 即可，**不会覆盖你的业务代码**。

---

## 这是什么 / 不是什么

**是**：一个跑在 Windows 上、以你**本人微信号**身份收发消息的 AI 机器人业务层。

**不是**：官方机器人、公众号、企业微信；也不是 Hook/DLL 注入类方案。

**⚠️ 先读风险**：微信安全中心 2026-01-30 的公告把"模拟按键、自动化脚本实现自动回复"明确列为**违规外挂**。使用本项目可能导致**账号被限制或封禁**。仅供学习研究，**账号风险自担**。

---

## 为什么要有这个项目

已有的成品包（`wechatbot-new` 等）能用，但业务层实测有这些问题：

| 问题 | 实测证据 |
|---|---|
| 慢 | 一条回复端到端 **28 秒**：队列 1s + 主模型 2.7s + **辅助模型（情绪判断）4.7s** + UI 发送校验 2s，再乘 8 条分段 |
| 碎 | 一条回复被拆成 **7-8 条**微信消息，每条间隔 3-5 秒 |
| 识图不通 | 群聊图片因为"没有文字、不可能带 @"被触发判定丢弃；视觉接口还被指向了文本模型端点 |
| 上下文写死 | `CONTEXT_MAX_CHARS = 2500`，聊十来句就忘前文 |
| 配置会被重写 | 网页控制台点一次"保存"就整体重写 `config.py`，曾把监听名单清空 |
| 日志乱码 | 日志写 **GBK**，排查问题时满屏乱码 |

本项目针对以上逐条重写业务层。

## 架构

```
        ┌──────────────── 本包（wechat-agent-lite）────────────────┐
        │  listener.py   触发判定 / 编排                          │
        │  vision.py     取图 + 视觉识别                          │
        │  brain.py      OpenAI 兼容对话 / 视觉调用               │
        │  context.py    上下文（可配长度，落盘留全量）            │
        │  sender.py     分段控制 + 发送                          │
        └───────────┬──────────────────────────┬─────────────────┘
                    │ 收（读数据库，不需要窗口）  │ 发（UI 操作）
        ┌───────────▼──────────────────────────▼─────────────────┐
        │  wechatauto-replica 引擎（Apache-2.0）                  │
        │  db.Listener（增量轮询，水位落盘，会话内保序）           │
        │  media.MediaDownloader（图片落盘解密）                   │
        │  guia.WeChatGUI（发送 / @ / 回复）                       │
        └─────────────────────────────────────────────────────────┘
```

**关键设计**：**收消息走数据库增量轮询，不走 UI 自动化**。这意味着收消息**不需要微信窗口在前台**，也绕开了 UI 自动化最脆弱的一面。只有"发送"才需要操作窗口。

## 安装

```bash
# 1. 前提：Windows + 微信 PC 版 4.1.x 已登录
# 2. Python >= 3.10
pip install -e .

# 3. 准备配置
cp config.example.yaml config.yaml
# 编辑 config.yaml：填 api_key、改 listen 里的会话名
```

密钥建议走环境变量，避免明文进 git：

```bash
set WAL_LLM_KEY=sk-xxxx        # Windows
```

## 使用

```bash
# 先自检（不发任何消息，只验证环境）
python -m wechat_agent -c config.yaml --check

# 正式跑
python -m wechat_agent -c config.yaml
```

`--check` 会依次验证：配置文件 → 人格提示词 → 微信数据库能否连上 → 监听目标能否解析（昵称→username）→ 模型接口能否调通。

## 配置要点

见 `config.example.yaml`（每一行都有注释）。几个关键项：

| 配置 | 默认 | 说明 |
|---|---|---|
| `send.max_segments` | `1` | 一条回复最多拆几段。**1 = 不拆**（旧包会拆成 7-8 条） |
| `context.max_chars` | `12000` | 送给模型的历史字符上限（旧包写死 2500） |
| `group.at_image_followup_sec` | `60` | 群里被 @ 后这么多秒内发来的图片按"续接"处理 |
| `vision.model` | `deepseek-chat` | ⚠️ **不要填推理模式的模型名**（见下） |
| `listener_interval` | `1.0` | 数据库轮询间隔（秒） |

### ⚠️ 关于视觉模型的坑（实测）

用 `deepseek-flash` 做识图时，它会把 `max_tokens` **全部烧在 `reasoning_tokens`** 上，`content` 返回**空字符串**，而且 HTTP 200 不报错——看起来"识别成功但没内容"。

同样请求换成 `deepseek-chat` 就正常。所以识图请用**非推理模式**的模型，或把 `max_tokens` 调到 1000+。

## 隐私与正确性设计（这几条不是可选项）

### 群聊图片必须绑定到"人"，不能绑定到"群"

最初的写法是"该群最近 60 秒被 @ 过就认图"。**这是个数据外传漏洞**：
A 提问之后，B 在群里发的私人截图会被当成 A 的续图**上传给远程模型**。

现在的规则（见 `listener.ImageRequestTracker`，有专门的测试覆盖）：

- "等图权"绑定到 **`(群, 发送者)`**，**只有发起 @ 的那个人**能消费掉；
- 额度有界：默认 1 张；消息里明确提到"图 / 照片 / 截图 / 看这"才放宽到 `image_followup_budget` 张；
- **其他人发的图、机器人自己的回复，都不会消耗或延长它**；
- **没被请求的图片一律不下载、不上传** —— 只在内存里留一条消息引用，
  用于支持"先发图、再 @ 机器人问这是什么"这个常见顺序（TTL 用同一套）；
- 超时即失效。

### 发送失败不自动重试

UI 自动化有个绕不开的状态：**已经按了回车，但校验超时** —— 消息可能发出去了也可能没有。
这时重试可能变成"重复发送"。所以本项目选择：**发送未确认成功 → 记日志、不写入上下文、不自动重发**。宁可漏一条，也不要在群里刷屏。

### 收消息不需要微信窗口

收消息走**数据库增量轮询**（引擎的 `db.Listener`），所以锁屏、窗口最小化都不影响接收；
只有**发送**才需要窗口可操作。这也让"机器人看不到消息"这类故障少了一大类。

## 已知限制（诚实清单）

- **端到端尚未在真机验证**：离线逻辑（配置/分段/上下文/前缀剥离/**等图归属**）有自测覆盖，
  图片链路（下载 + 识别）也已在真机跑通，但完整的收发闭环需要在装了微信的机器上实测。
- **延迟不是一个固定数字**：`3-5 秒` 只对**低负载 + 短文本**有希望。
  实测参考：模型调用 0.78s（短回）、图片下载 0.89s + 视觉识别 2.20s。
  长回答、长上下文、并发请求、图片场景都会更慢，不要用同一个目标去卡。
- **同一时间只能有一套程序监听同一个微信号**：跑本项目前请停掉其他机器人（包括旧包）。
- **发送依赖 UI 自动化**：微信窗口必须存在且可操作；锁屏、分辨率变化、微信弹窗都可能让发送失败
  （引擎会报错，本项目不会盲猜坐标重发）。
- **`MediaDownloader` 的图片档位**：默认 `tier='best'`（原图 > 压缩版 > 缩略图）。
  本机可能只有缩略图，识别质量会打折。
- **群聊 @ 识别是启发式的**：按文本里的 `@昵称` 匹配（昵称取本机微信昵称）。
  引用/转发里出现的 `@昵称` 也可能被算作 @，改名后需重启。
- **没有限流和费用上限**：私聊配置为 `always` 时，任何人都能持续消耗你的 API 额度。
  需要的话请自行加白名单或改成 `keyword` 模式。
